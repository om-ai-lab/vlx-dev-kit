# 1.2 System Flashing

The VLX Development Module is flashed with the NVIDIA JetPack 7.2 / Jetson Linux R39.2 toolchain. Production uses initrd Recovery USB; after-sales standalone recovery can use an ISO-bootable USB drive. This chapter covers the complete process from factory flashing to after-sales recovery.

## Factory Flashing Process

Factory production must use NVIDIA's official initrd flashing tool together with VLX identity registration. Deploy the VLX Factory Bundle after flashing to initialize the permanent device runtime entitlement.

1. Freeze the signed system package, custom board configuration, partition layout, and VLX Factory Bundle.
2. Switch the device to Force Recovery mode and connect it to the flashing host with a high-quality USB cable.
3. Flash internal storage with `l4t_initrd_flash.sh`; reset the device and verify the system version and partitions.
4. Deploy the VLX Factory Bundle, inject the device serial number, and have the secure chip generate keys and register the device certificate.
5. Issue only short-term factory test entitlements; do not pre-install the customer's permanent license.
6. Run line validation covering hardware interfaces, versions, MiniOS, database, license agent, and standard VLX-Seek inference.
7. After validation passes, clear factory credentials, package the device, and set its status to “Pending activation.”

### Factory Production Flash Command

```bash
# NVIDIA official production flashing command
# Run from Linux_for_Tegra/tools/kernel_flash
# Replace <board> with the frozen configuration name for the VLX carrier board

sudo ./l4t_initrd_flash.sh --no-flash <board> internal

# --no-flash: generate the image package
# --flash-only: perform flashing
# --massflash: enable parallel flashing at multiple stations

# After flashing, Thor remains at the initrd prompt and must be reset manually
./tools/board_automation/boardctl -t thor-jetson reset
