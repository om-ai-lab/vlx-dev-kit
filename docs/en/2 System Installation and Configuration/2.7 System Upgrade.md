# 2.7 System Upgrade

<div style="padding: 12px 16px; background-color: #FFF7E6; border-left: 4px solid #FA8C16; color: #613400;">

<strong>Note:</strong> A system upgrade is high risk because it changes the application, models, and database together. Follow this process strictly; do not skip any failed step.

</div>

1. Read the release notes and confirm the hardware version, current version, entitlements, and maintenance window.
2. Run the upgrade pre-check; do not skip any failed item.
3. Create and verify a database backup.
4. Download online or import an offline package; installation is allowed only after signature verification.
5. Keep power and network stable during installation; do not interrupt it.
6. Complete the upgrade after health checks pass. If it fails, wait for automatic rollback and do not force a repeated upgrade.

## Required Release-note Fields

Every system upgrade package must include structured release notes containing at least:

- Component version, release date, and release channel
- New features, changes, fixes, and known issues
- Hardware and license compatibility scope
- Database changes, including migration scripts and backward compatibility
- Download size, required disk space, and estimated downtime
- Upgrade paths and rollback limitations
- Security advisory ID and risk level
