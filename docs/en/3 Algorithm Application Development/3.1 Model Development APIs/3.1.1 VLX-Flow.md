# 3.1.1 VLX-Flow Development API

The VLX-Flow series is designed for video understanding and accepts video and text together. It supports video content understanding, scene analysis, stream-state assessment, and event recognition.

When calling VLX-Flow, provide a video input and a text prompt. The model returns an analysis based on the video and instruction.

## Use Cases

| Scenario | Description |
| --- | --- |
| Video understanding | Analyze subjects, scenes, actions, and events in a video. |
| Video Q&A | Ask questions about a video and have the model answer from its content. |
| Scene-state assessment | Determine whether a specified scene or state appears. |
| Abnormal behavior analysis | Analyze whether abnormal behavior or events occur. |
| Video-stream analysis | Understand content and state from an accessible stream. |

## Call Flow

Use the following flow when calling VLX-Flow:

1. Prepare the video input.
2. Call the VLX-Flow API with the video address and text prompt.
3. Read the model response as `text/event-stream`.
4. Call the stop API when the task ends or further analysis is no longer needed.

## Model API

### Endpoint

```http
POST {API_ENDPOINT}/os/v2/vlx/stream
```

The response type is `text/event-stream`; read the response as a stream.

### Request Headers

```http
Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=
Content-Type: application/json
Accept: text/event-stream
```

### Input Requirements

VLX-Flow requires both a video and a text prompt.

| Input | Required | Description |
| --- | --- | --- |
| Video | Yes | Video content for analysis. |
| Text prompt | Yes | Describes the task the model should perform. |

### Video Input Methods

The developer platform supports these video sources:

| Source | Description |
| --- | --- |
| Uploaded file | Call the upload API, then pass the returned file address to the model API. |
| Video file URL | Use a video file URL accessible to the platform. |
| Video stream URL | Use an accessible RTSP address. |
| Preset video | Default demo video provided on the model experience page. |

When calling the API, ensure that the platform services can access the video address.

### Request Parameters

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `model` | string | Yes | Model ID; always `vlx-flow`. |
| `source` | object | Yes | Video source information. |
| `prompt` | string | Yes | User prompt describing the analysis task. |
| `system_prompt` | string | No | Constrains the model role, analysis target, or response style. |
| `interval_seconds` | number | No | Video sampling/analysis interval in seconds. |
| `frame_preempt` | string | No | Consecutive-frame mode: `queue`, `preempt`, or `qa`. |
| `max_tokens` | integer | No | Maximum generated tokens; 20 is recommended. |
| `temperature` | number | No | Generation randomness; higher values are more diverse, lower values more stable. |

#### source Parameter

`source` carries video source information.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `source.path` | string | Yes | Video address: an uploaded file address, accessible file URL, or RTSP address. |
| `source.type` | string | Yes | Source type: `1` for RTSP stream, `2` for video file. |

#### frame_preempt Parameter

`frame_preempt` controls how results from consecutive frames are handled.

| Value | Description |
| --- | --- |
| `queue` | Later-frame results do not interrupt earlier streaming output, but are stored in context. |
| `preempt` | Later-frame results interrupt earlier streaming output; unsent results from earlier frames are stored in context. |
| `qa` | Multi-turn Q&A. Start with a question; the first sampled frame is sent with that question and each question is answered once. The task then continues and consumes tokens. Running tasks support multiple rounds; later analysis interrupts unfinished output and stores unsent results in context. |

### Request Examples

#### Call the Model After Uploading a Video

First upload a local video file:

```bash
curl --location --request POST '{API_ENDPOINT}/os/uploadFile' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --form 'file=@/path/to/video.mp4' \
  --form 'type="video/mp4"'
```

Then pass the returned video address in `source.path`.

#### Use a Video File URL

```bash
curl --location --request POST '{API_ENDPOINT}/os/v2/vlx/stream' \
  --header 'Accept: text/event-stream' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --data-raw '{
    "model": "vlx-flow",
    "prompt": "Explain the coffee-making steps in real time, in no more than 20 words",
    "system_prompt": "",
    "interval_seconds": 1,
    "frame_preempt": "queue",
    "temperature": 0.7,
    "max_tokens": 20,
    "source": {
      "path": "https://platform.om-agent.cn/minio/goal/cover/vlxflow-video04.mp4",
      "type": "2"
    }
  }'
```

#### Use an RTSP Address

```bash
curl --location --request POST '{API_ENDPOINT}/os/v2/vlx/stream' \
  --header 'Accept: text/event-stream' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --data-raw '{
    "model": "vlx-flow",
    "prompt": "Determine whether the current scene in the video is normal",
    "system_prompt": "",
    "interval_seconds": 1,
    "frame_preempt": "queue",
    "temperature": 0.7,
    "max_tokens": 20,
    "source": {
      "path": "rtsp://example.com/live/stream",
      "type": "1"
    }
  }'
```

### Response

On success, the API returns a `text/event-stream`. Read the SSE response until the server ends output or the client stops the task.

#### Streaming Response Example

```text
data: {"content":"race car","event":"delta","frameNo":8,"imageUrl":...}
data: {"content":"out of control","event":"delta","frameNo":8,"imageUrl":...}
data: {"event":"done","frameNo":10,"imageUrl":...}
```

#### Response Fields

| Field | Description |
| --- | --- |
| `taskId` | Task ID. Pass this ID to the stop API; the exact field location depends on the response. |
| `data` | SSE payload. Each `data` line is one streamed fragment. |
| `content` | Text fragment generated by the model. The exact field name depends on the response. |
| `[DONE]` | End-of-stream marker. |

## Stop API

You must call the stop API after running VLX-Flow. It stops the specified task, releases resources, and prevents further sampling.

### Endpoint

```http
POST {API_ENDPOINT}/os/v2/vlx/stop
```

### Request Headers

```http
Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=
Content-Type: application/json
```

### Request Parameters

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `taskId` | string | Yes | ID of the task to stop, returned by the model API. |

### Request Example

```bash
curl --location --request POST '{API_ENDPOINT}/os/v2/vlx/stop' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --data-raw '{
    "taskId": "222"
  }'
```

### Response Example

```json
{
  "code": 0,
  "message": "success"
}
```

## Usage Recommendations

For more stable results:

- Use a clear, stable, accessible video source.
- Prefer MP4 uploads; each file should be no larger than 500 MB.
- Keep video content aligned with the prompt.
- Make prompts explicit about the objects, actions, or events to monitor.
- Confirm that an RTSP stream is accessible before use.
- Video tasks usually take longer; avoid repeated submissions in quick succession.
- Before batch processing, validate quality and quota usage with a small sample.
- Always call the stop API when a task ends.
- If an error occurs, use the obtained `taskId` to call the stop API.

## Video File Recommendations

When uploading or passing a video file:

| Item | Recommendation |
| --- | --- |
| Format | MP4 |
| File size | No more than 500 MB per file |
| Length | Use a short video for initial testing |
| Quality | Clear frames; avoid severe blur, occlusion, or darkness |
| Content | Relevant to the prompt; avoid excessive unrelated content |
