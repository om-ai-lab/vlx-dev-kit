# 3.1.1 VLX-Flow 开发接口

VLX-Flow 系列是面向视频理解场景的 VLX 模型，支持视频和文本共同输入。适用于视频内容理解、视频场景分析、视频流状态判断和视频事件识别等场景。

调用 VLX-Flow 系列时，需要提供视频输入和文本提示词。模型会根据视频内容和文本指令返回分析结果。

## 适用场景

| 场景 | 说明 |
| --- | --- |
| 视频内容理解 | 分析视频中的主体、场景、动作和事件。 |
| 视频问答 | 针对视频内容提出问题，让模型根据视频回答。 |
| 场景状态判断 | 判断视频中是否出现指定场景或状态。 |
| 异常行为分析 | 分析视频中是否存在异常行为或异常事件。 |
| 视频流分析 | 对可访问的视频流进行内容理解和状态判断。 |

## 调用流程

使用 VLX-Flow 系列时，按以下流程完成调用：

1. 准备视频输入。
2. 调用 VLX-Flow 模型接口，传入视频地址和文本提示词。
3. 按 `text/event-stream` 读取模型返回结果。
4. 任务结束或不再需要继续分析时，必须调用停止运行接口。

<div style="padding: 12px 16px; background-color: #FFF7E6; border-left: 4px solid #FA8C16; color: #613400;">

VLX-Flow会持续对视频进行采样和分析。运行结束后请及时调用停止运行接口，避免任务继续运行并产生额外资源消耗。

## 模型调用接口

### 请求地址

```http
POST {API_ENDPOINT}/os/v2/vlx/stream
```

接口返回类型为 `text/event-stream`，调用方需要按流式响应读取返回内容。

### 请求头

```http
Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=
Content-Type: application/json
Accept: text/event-stream
```

### 输入要求

VLX-Flow 需要同时提供视频和文本提示词。

| 输入 | 是否必选 | 说明 |
| --- | --- | --- |
| 视频 | 是 | 用于模型分析的视频内容。 |
| 文本提示词 | 是 | 用于说明希望模型完成的任务。 |

### 视频输入方式

开发者平台支持以下视频输入方式：

| 视频源 | 说明 |
| --- | --- |
| 上传视频文件 | 先调用上传接口获取视频文件地址，再将地址传入模型调用接口。 |
| 视频文件地址 | 使用平台可访问的视频文件 URL。 |
| 视频流地址 | 使用可访问的 RTSP 地址作为视频源。 |
| 预设视频 | 平台在模型体验页中提供的默认体验视频。 |

通过 API 调用时，请确保传入的视频地址可以被平台服务访问。

### 请求参数

| 字段 | 类型 | 必选 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 是 | 模型 ID，固定传 `vlx-flow`。 |
| `source` | object | 是 | 视频源信息。 |
| `prompt` | string | 是 | 用户提示词，用于说明希望模型完成的分析任务。 |
| `system_prompt` | string | 否 | 系统提示词，用于约束模型角色、分析目标或回答风格。 |
| `interval_seconds` | number | 否 | 视频采样或分析间隔，单位为秒。 |
| `frame_preempt` | string | 否 | 连续帧分析模式，支持 `queue`、`preempt`、`qa`。 |
| `max_tokens` | integer | 否 | 限制模型生成内容的最大 Token 数，建议设置为20。 |
| `temperature` | number | 否 | 控制生成结果随机性，值越大结果越多样，值越小结果越稳定。 |

#### source 参数

`source` 用于传入视频源信息。

| 字段 | 类型 | 必选 | 说明 |
| --- | --- | --- | --- |
| `source.path` | string | 是 | 视频地址，可为上传接口返回的视频文件地址、平台可访问的视频文件 URL 或 RTSP 地址。 |
| `source.type` | string | 是 | 视频源类型。`1` 表示 RTSP 视频流地址，`2` 表示视频文件地址。 |

#### frame_preempt 参数

`frame_preempt` 用于控制连续帧分析结果的处理方式。

| 取值 | 说明 |
| --- | --- |
| `queue` | 后续帧分析结果不打断前面帧的流式输出，但会将结果存储到上下文。 |
| `preempt` | 后续帧分析结果打断前面帧的流式输出，前面帧未输出的分析结果会存储到上下文。 |
| `qa` | 多轮问答模式。必须以提问发起任务，任务开始执行后首次抽到图会携带问题向模型提问，每个问题仅回答一次，答案返回后任务会继续执行并消耗 Token ，运行中的任务可以持续多轮问答，后续分析结果会打断前置问题未完成的流式输出，前面帧未输出的分析结果会存储到上下文。 |

### 请求示例

#### 上传视频后调用模型

先上传本地视频文件：

```bash
curl --location --request POST '{API_ENDPOINT}/os/uploadFile' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --form 'file=@/path/to/video.mp4' \
  --form 'type="video/mp4"'
```

再将上传接口返回的视频地址传入 `source.path`

#### 使用视频文件地址

```bash
curl --location --request POST '{API_ENDPOINT}/os/v2/vlx/stream' \
  --header 'Accept: text/event-stream' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --data-raw '{
    "model": "vlx-flow",
    "prompt": "同步讲解咖啡制作步骤，内容 20 字以内",
    "system_prompt": "",
    "interval_seconds": 1,
    "frame_preempt": "queue",
    "temperature": 0.7,
    "max_tokens": 20,
    "source": {
      "path": "https://platform.om-agent.cn/minio/goal/cover/vlxflow-video04.mp4",
      "type": "2"
    }
  }'
```

#### 使用 RTSP 地址

```bash
curl --location --request POST '{API_ENDPOINT}/os/v2/vlx/stream' \
  --header 'Accept: text/event-stream' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --data-raw '{
    "model": "vlx-flow",
    "prompt": "请判断视频中当前场景是否处于正常状态",
    "system_prompt": "",
    "interval_seconds": 1,
    "frame_preempt": "queue",
    "temperature": 0.7,
    "max_tokens": 20,
    "source": {
      "path": "rtsp://example.com/live/stream",
      "type": "1"
    }
  }'
```

### 返回结果

请求成功后，接口会以 `text/event-stream` 返回流式数据。调用方需要按 SSE 格式持续读取服务端返回内容，直到服务端结束输出，或业务侧主动停止任务。

#### 流式返回示例

```text
data: {"content":"赛车","event":"delta","frameNo":8,"imageUrl":...}
data: {"content":"失控","event":"delta","frameNo":8,"imageUrl":...}
data: {"event":"done","frameNo":10,"imageUrl":...}
```

#### 返回字段说明

| 字段 | 说明 |
| --- | --- |
| `taskId` | 任务 ID。停止运行时需要传入该 ID，具体字段位置以接口实际返回为准。 |
| `data` | SSE 数据内容。每条 `data` 表示一次流式返回片段。 |
| `content` | 模型生成的文本片段。具体字段名称以接口实际返回为准。 |
| `[DONE]` | 流式输出结束标记。 |

## 停止运行接口

VLX-Flow 运行后必须调用停止运行接口。该接口用于停止指定任务，释放运行资源，并避免任务继续采样分析。

### 请求地址

```http
POST {API_ENDPOINT}/os/v2/vlx/stop
```

### 请求头

```http
Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=
Content-Type: application/json
```

### 请求参数

| 字段 | 类型 | 必选 | 说明 |
| --- | --- | --- | --- |
| `taskId` | string | 是 | 需要停止的任务 ID。该 ID 来自模型调用接口返回结果。 |

### 请求示例

```bash
curl --location --request POST '{API_ENDPOINT}/os/v2/vlx/stop' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer YjI3YjM4OTQyZDczMjZkMWUzYTdAZVpHVWdxdzg=" \
  --data-raw '{
    "taskId": "222"
  }'
```

### 返回示例

```json
{
  "code": 0,
  "message": "success"
}
```

## 常用提示词示例

| 场景 | 提示词示例 |
| --- | --- |
| 视频内容描述 | 实时解说赛场车况，内容控制在 20 字内 |
| 场景分析 | 实时描绘空中全景画面，字数 20 字以内 |
| 目标行为分析 | 点评制作手法与精彩细节，20 字以内 |
| 状态识别 | 点评车辆飞驰的精彩画面，20 字以内 |

## 调用建议

为了获得更稳定的效果，建议：

- 使用清晰、稳定、可访问的视频源。
- 上传视频文件时，优先使用 MP4 格式，单个文件不超过 500MB。
- 视频内容尽量与提示词目标一致。
- 提示词尽量明确，说明需要模型关注的对象、行为或事件。
- 使用 RTSP 地址时，先确认视频流地址可访问。
- 视频类任务处理时间通常更长，请避免短时间内重复提交。
- 批量处理视频前，先用少量样本验证效果和额度消耗。
- 任务结束后必须调用停止运行接口，避免任务继续运行。
- 如果调用过程中发生异常，也建议使用已获取到的 `taskId` 调用停止运行接口。

## 视频文件建议

上传或传入视频文件时，建议：

| 项目 | 建议 |
| --- | --- |
| 文件格式 | 使用 MP4。 |
| 文件大小 | 单个文件不超过 500MB。 |
| 视频长度 | 首次调试建议使用较短视频。 |
| 视频质量 | 画面清晰，避免严重模糊、遮挡或过暗。 |
| 视频内容 | 与提示词任务相关，避免无关内容过多。 |
